39 --- 2. Distributed Systems Patterns: Transactional Outbox, CQRS
&
Distributed Locking To ensure high reliability and eliminate split-brain hazards in railway operations, RailSync integrates three core distributed systems patterns: 1. Transactional Outbox Pattern with Change Data Capture
(CDC): In distributed systems, updating a
relational database and publishing an event to a
message broker in separate operations introduces a
'dual-write hazard'
—
if the broker crashes after the database commits, downstream systems never receive the event. RailSync eliminates this hazard by implementing the Transactional Outbox pattern:
●
Atomic Local Transaction: When an event state transition occurs
(e.g., Stage 04 to Stage 05), the application writes the updated OperationalEvent entity and an OutboxEvent record into the PostgreSQL database within the same atomic ACID database transaction.
